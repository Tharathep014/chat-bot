# ผู้ช่วยตารางสอน — ฉบับปรับปรุง

เว็บแชทภาษาไทยสำหรับข้อมูลใน `server/data/schedule.json` โดยเฉพาะ ใช้ React + Vite และ Node.js + Express

## สิ่งที่ปรับปรุง

- ค้นข้อมูลจากตารางโดยตรงและแนบแหล่งข้อมูลทุกคำตอบที่พบข้อมูล ไม่เรียกโมเดลภายนอกและไม่ต้องใช้ API key
- ถ้าคำถามนอกขอบเขต ตอบว่า “ตอบให้ไม่ได้ค่ะ ฉันตอบได้เฉพาะข้อมูลในตารางสอนนี้…”
- ถ้าไม่พบวิชา ห้อง กลุ่ม หรือวันในไฟล์ จะบอกว่าไม่พบข้อมูล ไม่เดาว่าไม่มีเรียน
- ถามต่อเนื่องได้ เช่น “วิชาฐานข้อมูลวันจันทร์เรียนห้องไหน” แล้วถาม “แล้ววันพุธล่ะ”
- ดูและค้นตารางควบคู่กับแชท ใช้ได้บนมือถือ มีตัวอย่างคำถาม แหล่งอ้างอิง และลองส่งใหม่เมื่อเชื่อมต่อผิดพลาด
- ตรวจข้อมูลและรูปแบบคำขอ จำกัดข้อความและประวัติ พร้อมชุดทดสอบการค้นข้อมูล/API

## เริ่มใช้งาน

ใช้ Node.js 20 ขึ้นไป (ทดสอบบน Node.js 22) เปิด terminal ที่โฟลเดอร์นี้แล้วรัน:

```sh
npm run setup
npm run dev
```

เปิด http://127.0.0.1:5173 ฝั่ง API ใช้พอร์ต 3001 กด Ctrl+C เพื่อปิดทั้งสองส่วน

หากมี `node_modules` อยู่ครบแล้ว ข้าม `npm run setup` ได้

สำหรับเปิดจากไฟล์ที่ build แล้ว:

```sh
npm run build
npm start
```

เปิด http://127.0.0.1:3001 ทั้งหน้าเว็บและ API จะทำงานบนพอร์ตเดียวกัน

การตั้งค่าเพิ่มเติมไม่จำเป็น หากต้องเปลี่ยนพอร์ตให้คัดลอก `server/.env.example` เป็น `server/.env` แล้วแก้ PORT ค่า HOST เริ่มต้นคือ 127.0.0.1 สำหรับใช้งานบนเครื่องนี้ คำสั่ง `npm run dev` จะตั้ง proxy ตาม PORT โดยอัตโนมัติ

## ตัวอย่างคำถาม

- วันจันทร์มีสอนวิชาอะไรบ้าง
- วิชา 31901-2007 เรียนห้องไหน
- วิชาฐานข้อมูลกี่หน่วยกิต
- กลุ่ม สท.4/2 เรียนวันไหน
- วันพุธเวลา 09:00 เรียนอะไร
- วันจันทร์คาบที่ 6 เรียนอะไร
- วันนี้มีเรียนอะไร
- ครูชื่ออะไร
- รวมชั่วโมงสอนเท่าไร
- สอนวิชาอะไรบ้าง / สอนวันไหนบ้าง / สอนกี่วัน
- วันจันทร์สอนกี่คาบ / วันนึงสอนกี่คาบ / ทั้งอาทิตย์สอนกี่คาบ
- คาบละกี่ชั่วโมง / หนึ่งคาบกี่นาที
- วันจันทร์เริ่มสอนกี่โมง / เลิกสอนกี่โมง / คาบแรกวันพุธเรียนอะไร / วันจันทร์สอนติดกันกี่คาบ
- ตอนนี้สอนอะไรอยู่ / คาบต่อไปเรียนอะไร
- วันไหนสอนเยอะสุด / วิชาไหนสอนเยอะสุด / ห้องไหนใช้บ่อยสุด
- สอนห้องไหนบ้าง / มีกลุ่มอะไรบ้าง / ใครสอนฐานข้อมูล
- บ่ายโมงวันจันทร์สอนอะไร / สี่โมงเย็นวันพุธเรียนอะไร
- ภาษาอังกฤษพื้นฐาน เช่น what subjects do you teach, how many periods on monday
- ครูสจีสอนวิชาอะไร / ใครสอนวิชา 30001-1003 / รายชื่อครูทั้งหมด (ข้อมูล OCR ภาคเรียน 1/2568 ไม่มีวันและเวลา)

คำถามครึ่งประโยคหรือพิมพ์ผิดเล็กน้อยยังตอบได้ เช่น "จันทร์", "ศุกสอนไร", "ฐานข้อมูล", "บ่ายนี้สอนมั้ย" ส่วนเลขกลุ่มที่ไม่มีคำนำหน้า เช่น "4/2" จะถามกลับว่าหมายถึง สท.4/2 หรือ คภ.4/2 คำทักทายและคำขอบคุณจะได้คำแนะนำวิธีถาม

คำถามเล่นหรือนอกเรื่อง เช่น ครูหล่อไหม หรือ 1+1 เท่าไร จะถูกปฏิเสธแบบเป็นกันเอง คำหยาบจะถูกปฏิเสธอย่างสุภาพ ส่วนคำถามเกี่ยวกับเนื้อหาบทเรียน สภาพอากาศ ข่าว คำสั่งให้แต่งข้อมูล หรือคำถามนอกเรื่องที่ต่อท้ายคำถามตารางสอน จะถูกปฏิเสธทั้งข้อความ ตัวค้นนี้รองรับรูปแบบภาษาไทยที่กำหนดไว้ ไม่ใช่แชททั่วไป ตัวอย่างคำถามที่ทดสอบไว้ทั้งหมดอยู่ใน `server/test/questions.test.js`

“วันนี้/พรุ่งนี้” อิงวันในเขตเวลา Asia/Bangkok และตารางประจำสัปดาห์ ไม่ยืนยันวันหยุด การสอบ หรือการเปลี่ยนแปลงในวันที่จริง คำถามตามวันที่ปฏิทิน เช่น "วันที่ 5" จะให้ถามเป็นวันในสัปดาห์แทน

## แก้ไขตาราง

แก้ไข `server/data/schedule.json` แล้วเริ่ม server ใหม่ โครงสร้างแบ่งเป็น `meta`, `courses`, `totals`, `periods` และ `weeklySchedule` รหัสวิชาในแต่ละคาบต้องอ้างถึงรายวิชาที่มีอยู่ เวลาต้องเป็น HH:mm-HH:mm โดยเวลาเริ่มน้อยกว่าเวลาสิ้นสุด

ข้อมูลต้นฉบับระบุว่าถอดจากภาพด้วยสายตา และพบตัวเลขชั่วโมงไม่สอดคล้องกัน:

| แหล่งข้อมูล | ชั่วโมง |
| --- | ---: |
| ช่องยอดรวม totals.hours | 33 |
| ผลบวก hours ของรายวิชา | 28 |
| ผลบวกช่วงเวลาในตารางรายวัน | 24 |

ระบบคงข้อมูลเดิมและแสดงแยกตามแหล่ง ไม่เลือกค่าใดเป็นค่าที่ถูกต้องโดยอัตโนมัติ ควรตรวจเทียบตารางต้นฉบับก่อนแก้ข้อมูล จำนวนผู้เรียนเป็นค่าของแต่ละรายการ ไม่ใช่ยอดคนไม่ซ้ำรวมทั้งสัปดาห์

## เก็บข้อมูลใน Supabase (ไม่บังคับ)

ถ้าไม่ตั้งค่าอะไร ระบบอ่านจาก `server/data/schedule.json` ถ้าตั้ง `SUPABASE_URL` และ `SUPABASE_KEY` ระบบจะอ่านจากฐานข้อมูล Supabase (PostgreSQL) แทน โค้ดตอบคำถามเหมือนเดิมทุกอย่าง

1. สร้างโปรเจกต์ที่ supabase.com
2. เปิด **SQL Editor** แล้วรัน `supabase/schema.sql` (สร้าง 10 ตาราง พร้อมสิทธิ์อ่านอย่างเดียว) ตามด้วย `supabase/seed.sql` (ใส่ข้อมูล)
3. เปิด **Project Settings → API** คัดลอก Project URL และ publishable (anon) key ใส่ใน `server/.env` (ดูตัวอย่างใน `server/.env.example`) และใน Vercel ที่ **Settings → Environment Variables** ห้ามใช้ secret/service_role key

แก้ข้อมูลได้ใน **Table Editor** ของ Supabase ระบบจะเห็นข้อมูลใหม่ภายใน 60 วินาที (ปรับด้วย `SCHEDULE_CACHE_SECONDS`) ถ้าแก้ `schedule.json` แล้วอยากส่งขึ้น Supabase ให้รัน `npm run supabase:seed` เพื่อสร้าง `seed.sql` ใหม่ แล้วรันใน SQL Editor ถ้า Supabase ล่ม ระบบใช้ข้อมูลชุดล่าสุดที่โหลดไว้ต่อ ถ้ายังไม่เคยโหลดได้เลย API จะตอบ 503

## API

- `GET /api/health` — สถานะ ระบบตอบจากตาราง และข้อสังเกตข้อมูล
- `GET /api/schedule` — ตารางที่ระบบใช้
- `POST /api/chat` — รับ `{ "message": "วันจันทร์มีสอนอะไร", "history": [] }`

ผลลัพธ์มี `reply`, `status`, `sources` และอาจมี `suggestions` โดย status เป็น answered, not_found, out_of_scope หรือ clarification

message ยาวไม่เกิน 1,000 ตัวอักษร history ไม่เกิน 12 ข้อความ มี role เป็น user/assistant และ text เป็นข้อความ ประวัติคำตอบของ assistant ไม่ถูกนำมาใช้เป็นแหล่งข้อมูล ข้อมูลที่ผู้ใช้พิมพ์ไม่มีสิทธิ์เปลี่ยนตาราง

## ทดสอบ

```sh
npm test
npm run build
```

ชุดทดสอบใช้ Node test runner ครอบคลุมวัน เวลา ขอบเขตช่วงเวลา วิชา กลุ่มเรียน คำถามต่อเนื่อง การปฏิเสธคำถามผสม/คำสั่งแทรก ข้อมูลขาดหาย ตัวเลขไม่ตรงกัน และ validation ของ API

โปรเจกต์ฉบับนี้อยู่ในโฟลเดอร์ `game` แยกจากโฟลเดอร์ต้นฉบับที่ผู้ใช้ส่งมา ไม่ต้องใช้ GitHub token หรือบริการ GitHub Models สำหรับการตอบคำถามอีกต่อไป
